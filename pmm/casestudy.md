# /pmm casestudy — Case Study Matcher
**Invoke:** `/pmm casestudy [customer name | vertical | region | use case]`

---

## Behavior Rules

1. Check for exact customer match first, then nearest match by vertical → region → use case
2. If multiple match equally well, surface the 2–3 best and ask which fits the pitch context
3. Never fabricate metrics — pull only from the verified library below
4. If asked to write a new case study format, ask: "Do you want to reference an existing customer or draft a new format?"
5. Always include "How to Use in Your Pitch" — this is what makes the output sales-ready, not just informational

---

## Output Format

```
# Case Study Match: [Customer Name]
**Segment:** [vertical] | **Region:** [geo] | **Use Case Match:** [why this fits the pitch]

## The Situation (1–2 sentences)
[What they were managing and what was breaking. Written to be read aloud in a discovery call.]

## The Problem That Mattered
[The sharpest pain — the one that actually drove the buying decision. Not a list — one thing.]

## What Facilio Did
- [Solution bullet 1 — outcome-framed, not feature-framed]
- [Solution bullet 2]
- [Solution bullet 3]

## The Proof
[2–3 impact metrics — verbatim from library below. No rounding up. No inflation.]

## The Quote
[Verbatim customer quote if available — use exact wording from library]

## How to Use in Your Pitch
[Where in the sales cycle this lands best — discovery, late stage, proposal, RFP. One sentence on how to introduce it naturally.]
```
