# /pmm battlecard — Competitive Battlecard
**Invoke:** `/pmm battlecard [maximo | fsi | mri | archibus | corrigo | siemens-navigator | legacy-cmms | own-vs-outsource]`

---

## Methodology

Build battlecards using three frameworks combined:

**1. SPIN Selling — Trap Questions (Neil Rackham)**
Four question types that surface pain the prospect hasn't articulated:
- Situation: Establishes their current state with the competitor
- Problem: Surfaces a specific pain the competitor creates
- Implication: Makes the cost of that pain visceral — "What happens when...?"
- Need-Payoff: Makes the prospect articulate what a better world looks like
Implication questions are the most powerful. Never name the competitor when asking them.

**2. Challenger Sale — Reframe Without Attacking**
Don't say "Maximo is bad." Say "When your system flags an issue — who takes the next action, the system or your team?" Let the prospect reach the conclusion. Facilio wins by reframing, not attacking.

**3. Win/Loss Lens**
The 3 real reasons Facilio loses deals and wins deals — embedded in the "when you'll see them" section. Most companies attribute losses to "price" — the real answer is usually product fit, sales process, or relationships.

**Kill Shot Rule:** One devastating, proof-backed statement saved for the final stage only. Never open with it. Used only when the deal is at risk.

## Competitor Data (Pre-Loaded)

### IBM Maximo
- Bolt-on AI only — reporting-focused, not workflow execution. Watson-powered overlay, not native FM engine.
- SI-dependent deployment — any customization requires a Maximo partner. No no-code/low-code.
- Aging UX — cumbersome, not built for mobile-first or multi-stakeholder access.
- Long implementation — months to years. Failed deployments are common.
- Cost escalation — every new use case = new SI engagement = new cost.
- Mobile: Optional add-on. Designed for field techs only — not FM managers, vendors, or clients.
- G2/TrustRadius reviews: "Setup rated 2/10 — very complicated." "Version fragmentation is a constant challenge."

### FSI
- Outdated UI — hard to navigate, non-intuitive. G2 reviews confirm "reminiscent of the 90s."
- Chargeable for every config change — any customization post-implementation is billed.
- No native mobile for all stakeholders — separate chargeable license, technicians only.
- 2–3 week support TAT — hard to reach, slow resolution.
- Implementation cost ≈ 60% of deal value — extremely expensive to deploy.
- No open API — new integrations are chargeable. No self-serve integration.
- Customer defections: Musanadah (charged flat fee per module + extra for every report), Engie (billed for every change).

### MRI (CaFM / Owner-Operator)
- Fragmented suite — multiple apps on different codebases. Multiple logins. Data loss risk between apps.
- FM is bolt-on to a finance product — not purpose-built for operations.
- Minimal workflow automation — must depend on software vendors for deployment and configuration.
- Dashboards spread across apps — relies on PowerBI for basic insights. Complex drill-down.
- Slow, complex implementation — separate onboarding per app. Inconsistent data flow.
- High TCO — multiple licenses + IT + integration + maintenance overhead.

### Siemens Navigator (Connected Buildings)
- Energy/FDD only — alarm doesn't auto-create work order. No FM workflow execution.
- Limited IoT readiness — connects primarily with BMS systems, not multi-vendor/multi-protocol.
- Not FMSP-friendly — designed for large corporates with dedicated energy teams.
- No FM operations integration — separate from maintenance, vendor, and compliance workflows.
- Unclear roadmap for ERP/CRM/comms integrations.

### Archibus / Eptura
- Space management heritage — weak on maintenance execution.
- Poor mobile experience — not built for field-first operations.
- Legacy architecture — customization requires technical resources, not no-code.

### Corrigo
- Work order only — no unified platform. No AI. No energy management.
- Owned by JLL — conflict of interest for FMSPs competing against JLL for contracts.

### Homegrown / Spreadsheets
- Scale wall — falls apart at multi-site or multi-client complexity.
- No audit trail — nothing is defensible in compliance or client reviews.
- Zero portfolio visibility — no aggregated reporting, no benchmarking.
- No AI capability — every decision is manual.

## Execution Rules

- Always give a fair, honest representation of what the competitor does well before attacking weaknesses. Credibility comes from honesty.
- Trap questions must never name the competitor. The prospect reaches the conclusion themselves.
- "Their attacks on Facilio" section must use real attacks AEs actually hear — not strawmen.
- Kill shot is used sparingly — only when the deal is genuinely at risk in the final stage.
- For own-vs-outsource: this is a positioning asset, not a competitor battlecard. Frame it as data sovereignty, not a competitive attack.
